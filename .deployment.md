# Deploy to OKE

Push to `master` to build an ARM64 image, publish it to GitHub Container Registry,
and deploy it to Oracle Kubernetes Engine. The workflow follows `commitr`'s
build → publish → apply → rollout pattern.

* `Dockerfile`: Apache/PHP and the application's extensions.
* `.apache.conf`: CMS routing and the original client IP behind Caddy.
* `.deployment.yml`: one pod containing the CMS, MariaDB, and Caddy for HTTPS.
* `.github/workflows/deploy.yml`: the commented GitHub Actions workflow.

PHP 8.3 is intentional: PHP 8.4 adds a built-in `mb_ucfirst()` that conflicts with
the application's existing helper. The application source is left unchanged.

## One-time setup

1. Point a hostname's DNS A record to `129.213.152.149`; set the repository's
   `CMS_HOSTNAME` Actions variable to that hostname, without `https://`.
2. Store the deployment service account's kubeconfig in the repository's
   `KUBECONFIG` Actions secret. Its Kubernetes Role is limited to namespace `cms`.
3. Create two Kubernetes Secrets in `cms`: `cms` contains a `private.php` file
   defining `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`, `ROOTPASS`, and `ADMINPASS`;
   `mariadb` contains `MARIADB_DATABASE=cms`, `MARIADB_USER=cms`, matching
   `MARIADB_PASSWORD`, and a separate `MARIADB_ROOT_PASSWORD`.
4. Allow HTTPS NodePort `30443` through the worker security list, alongside HTTP
   `30080`, and allow GitHub runners to reach the authenticated Kubernetes API.
5. Keep the `cms` container package public so OKE can pull it without a registry
   password. Anonymous pulls have been verified for this repository.

The existing Network Load Balancer is reused. Caddy handles certificate issuance
and renewal. Apache receives the public hostname and original client IP, and the
CMS loads its existing `private.php` configuration mechanism in production.

## Persistence

Database files, uploads, sessions, and certificates live under `/var/lib/cms` on
the worker's existing boot disk; there is no additional storage service.
Redeployments briefly stop the pod and reuse those files. **Back up before replacing
the worker or its boot disk:** this storage does not follow a replacement node.
Keep this deployment at one replica.

The application code is unchanged. In particular, `model/pix.php` currently resets
its imageboard tables on every request; disk persistence cannot prevent this.
The database initialization grants `SUPER` to the dedicated CMS database user
because existing models issue `SET GLOBAL` statements. MariaDB listens only
inside the pod and is not exposed through the load balancer.

`ROOTPASS` and `ADMINPASS` initialize the CMS accounts only on an empty database.
Change existing account passwords through the CMS, not by changing those values.
Rotate the GitHub service-account token by replacing its Kubernetes token Secret
and updating the GitHub `KUBECONFIG` secret.
